Why go-fileshare

The protocols do not agree about who is asking.

That is a fact about the protocols, not a limitation here. What a person can be served over depends on what the directory holds for them — so the honest thing is to compute that matrix and print it, rather than leave it to be discovered at a mount.

🔐

What proves somebody differs by protocol

SMB needs NTLMv2, so it needs the password or its MD4(UTF16LE(password)). S3 needs the password itself, because SigV4 is an HMAC computed from it. SFTP takes a public key or a certificate. A person holding only a key reaches SFTP and nothing else.

🚫

A refusal, not a warning

A share that names who may use it is not exported over NFS. A configuration saying photos belongs to alice and a protocol handing photos to whoever connects cannot both be honoured, and quietly widening access is the worse of the two failures.

🎫

Kerberos lifts that refusal

A kerberos block gives NFS something to check: sec=krb5 carries a principal a ticket proves, rather than a uid the client asserts. The realm is compared, not just the name before the @ — two realms can each have an alice.

📋

Said before it is served

fileshare check opens every image and prints every share against every protocol and every person against every protocol. A name that belongs to no user block is refused at startup rather than locking Alice out of her own share.

💽

One image, opened once

fat32, exfat, ext4, ntfs, ufs, iso9660, squashfs and hfs+, with apfs, btrfs, xfs and zfs by partition — read by go-filesystems. Every protocol shares that one open image behind one lock.

⚖️

Judged by other people's clients

Samba's smbclient, macOS's Finder, Windows' own redirector, OpenSSH's sftp, mount_nfs. A fixture built from one reading of a protocol can only confirm that reading — which is how the one defect only Windows could find was found.

What each protocol needs

Five answers to who is asking.

smb

NTLMv2. Needs the password, or its MD4(UTF16LE(password)) — an NT hash is enough, and is what a directory should hold if SMB is all it serves.

nfs

Nothing, on its own. AUTH_UNIX is a claim the client makes about itself and the wire cannot disagree with it — so a restricted share is not exported here at all, unless a kerberos block gives it sec=krb5.

webdav

HTTP Basic, or a bearer token an identity provider signed. The most forgiving of the five: a verifier the directory can only check is enough.

sftp

A public key or a certificate. Somebody with only authorized_keys reaches SFTP and none of the others — and somebody with only a password does not reach it.

s3

A SigV4 signature: an HMAC computed from the secret, which therefore has to be the password itself and not a hash of it. A share is a bucket.

File sharing that ships like Go.

No cgo, no frameworks, no runtime to install. A build tag leaves a protocol out of the binary entirely, and --isolate gives each one its own process, opening only the images it may serve. The people can come from a user block, a database or LDAP — the same users block authnd reads, so a site describes its directory once.
